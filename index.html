AgentArb — sample arbitration

Small-claims court for agent commerce. This page walks through a genuine arbitration produced by the AgentArb CLI — not a mockup. Every hash, rule, and verdict below is real output from a local demo run.

Sample data only. All identities, keys, and amounts are demo-generated fakes. Verdicts are advisory: AgentArb v1's escrow is a ledger model, not custody — it records holds, releases, and refunds, and moves no real money. A verdict takes effect only when a settlement adapter (Stripe, on-chain) honors it.

2. The evidence

The claimant submitted a signed evidence bundle. Every item is signed with the submitter's Ed25519 did:key identity, and the bundle is content-addressed by hash — so nobody can forge someone else's proof or quietly edit a claim after filing.

For a non-delivery claim, the decisive fact is an absence: the bundle contains no delivery proof at all, and the deadline has passed. That absence — checked against the signed record — is what the rules decide on.

Not all evidence is equal. AgentArb grades evidence into trust tiers: an admission signed by the other party counts most, independent third-party evidence counts next, your own signed word counts less, and unsigned claims count least. A second demo case shows a tier in action — a late-delivery claim backed by an oracle-signed carrier scan (“Carrier scan: delivered late”), graded tier 2, third-party-oracle-signed, which fired the delivered-late rule and refunded the agreed $15.00 penalty. If the evidence is too weak or contradictory, the engine says “I don't know” and escalates to a human instead of guessing.

3. The rule that fired

Rules are data, not code — a vendored JSONLogic engine that can only look at evidence, never run anything. The verdict cites the exact rule-set version and hash that decided it, and publishes its full reasoning trace, so anyone can re-check it.

The verdict is itself signed (Ed25519 did:key JWS) and its id is its content address — tamper with one byte and the id stops matching. Anyone with the files can verify bundle and verdict offline, without trusting the server that issued them.

5. The escrow movement

Money moves only on verdicts. Before adjudication, the respondent's side placed a $100.00 hold against the claim. The verdict then moved it — nothing moved on the claim alone, and a refund can never exceed the amount claimed.

hold_b85e250c…  hold    $100.00  → status: held
verdict v_7648…  refund  $100.00  → hold status: refunded, remaining: $0.00

Reminder: v1's escrow is a ledger model, not custody. These are records of holds, releases, and refunds that a real payment adapter settles against later — no real money moved here.

Run it yourself

npm install && npm run build
node packages/server/dist/index.js          # arbiter on 127.0.0.1:3000
node packages/cli/dist/index.js demo --scenario non-delivery --out /tmp/demo
node packages/cli/dist/index.js submit --server http://127.0.0.1:3000 --in /tmp/demo/bundle.json
node packages/cli/dist/index.js adjudicate --server http://127.0.0.1:3000 --case <case-id>
node packages/cli/dist/index.js verify --in /tmp/demo/bundle.json   # offline

Try the other scenarios too: late-delivery (refunds a pre-agreed penalty on oracle-signed proof) and wrong-partial-delivery (refunds the missing amount on credible inspection evidence).
